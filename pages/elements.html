HTML Elements

These sections cover the various HTML elements available in the DevDocs.

Quotes

Use <blockquote> for longer quotations or highlighted callout-style text that should remain semantically distinct from the surrounding content.

"Good documentation should be easy to scan, easy to trust, and easy to revisit later."

Some One :)

Code Blocks

DevDocs supports code blocks for displaying preformatted code snippets. These can be used to show examples, configurations, or any other code-related content. Code blocks are defined using the <pre> and <code> tags.

// Leaf node (has a page)
{
    id: 'installation',
    label: 'Installation',
    page: 'pages/installation.html'
}

// Group node (has children, no page)
{
    id: 'getting-started',
    label: 'Getting Started',
    children: [
    { id: 'intro', label: 'Introduction', page: 'pages/intro.html' }
    ]
}
ℹ Note
  • Each code block should be properly formatted to ensure readability and consistency.
  • Each code block has a copy button for easy copying.

Callouts

ℹ Note

This documentation site is served as a static project. No server-side rendering or framework is required. All you need is a basic local HTTP server or your IDE's Live Server extension.

⚠ Never Expose API Keys Client-Side

Any secret embedded in JavaScript that runs in the browser is publicly visible to anyone who opens DevTools. Route all privileged API calls through a backend proxy or serverless function.

✖ Trailing-slash paths

On GitHub Pages, make sure all page paths in NAV_DATA use a relative path from the repository root (e.g., pages/intro.html), not an absolute path starting with /, or your fetches will fail.

  <div class="callout-title">ℹ Info</div>
  <p>Your note here.</p>
</div>

Tab Panel

Use data-tab-panel to group related content into switchable tabs. Tabs are keyboard accessible - use the arrow keys, Home, and End while a tab is focused to move between them.

  • ArrowLeft / ArrowRight: Move between tabs
  • Home: Move to the first tab
  • End: Move to the last tab

Wrap each tab's markup in a .tab-panel-content element with an id matching its tab's data-tab-target.

Tab panel styling automatically follows the current light/dark theme, matching the rest of the documentation.

setupTabPanels() in app.js wires click and keyboard navigation for every [data-tab-panel] on the page.

<div class="tab-panel" data-tab-panel>
  <div class="tab-panel-nav" role="tablist" aria-label="Example tabs">
    <button type="button" class="tab-panel-tab is-active" role="tab"
      id="tab-html-btn" aria-controls="tab-html-panel" aria-selected="true"
      data-tab-target="tab-html-panel">HTML</button>
    <button type="button" class="tab-panel-tab" role="tab"
      id="tab-css-btn" aria-controls="tab-css-panel" aria-selected="false"
      tabindex="-1" data-tab-target="tab-css-panel">CSS</button>
  </div>
  <div class="tab-panel-panels">
    <div class="tab-panel-content is-active" role="tabpanel"
      id="tab-html-panel" aria-labelledby="tab-html-btn">
      <p>First tab's content.</p>
    </div>
    <div class="tab-panel-content" role="tabpanel" id="tab-css-panel"
      aria-labelledby="tab-css-btn" hidden>
      <p>Second tab's content.</p>
    </div>
  </div>
</div>
ℹ Note

Exactly one tab should start with is-active/aria-selected="true" and its matching panel without hidden. Every other tab needs tabindex="-1" so keyboard focus lands only on the active tab.

Vertical Tab Panel

Add the tab-panel--vertical modifier class to stack tabs in a side column instead of a row. It's the exact same .tab-panel-nav / .tab-panel-tab / .tab-panel-panels / .tab-panel-content markup and setupTabPanels() wiring - only CSS changes the layout, and the keyboard handler swaps to ArrowUp/ArrowDown automatically.

Same markup as the horizontal example - just add tab-panel--vertical next to tab-panel on the outer <div>.

The modifier re-flows .tab-panel-nav into a column and moves the active-tab indicator to the side border.

setupTabPanels() detects tab-panel--vertical and binds ArrowUp/ArrowDown instead of ArrowLeft/ArrowRight for tab navigation.

<div class="tab-panel tab-panel--vertical" data-tab-panel>
  <div class="tab-panel-nav" role="tablist" aria-label="Example vertical tabs">
    <button type="button" class="tab-panel-tab is-active" role="tab"
      id="tab-vert-html-btn" aria-controls="tab-vert-html-panel" aria-selected="true"
      data-tab-target="tab-vert-html-panel">HTML</button>
    <button type="button" class="tab-panel-tab" role="tab"
      id="tab-vert-css-btn" aria-controls="tab-vert-css-panel" aria-selected="false"
      tabindex="-1" data-tab-target="tab-vert-css-panel">CSS</button>
  </div>
  <div class="tab-panel-panels">
    <div class="tab-panel-content is-active" role="tabpanel"
      id="tab-vert-html-panel" aria-labelledby="tab-vert-html-btn">
      <p>First tab's content.</p>
    </div>
    <div class="tab-panel-content" role="tabpanel" id="tab-vert-css-panel"
      aria-labelledby="tab-vert-css-btn" hidden>
      <p>Second tab's content.</p>
    </div>
  </div>
</div>
ℹ Note

The vertical tabs falls back to a horizontal tab row once the .content-body container itself narrows below 600px - so it reacts to the content area's actual width (sidebar state included), not just the browser window.
