Parent Attributes / Tags System

A dynamic, five-type tagging system built for a real Adilas e-commerce customer, letting products carry flexible, searchable attributes on top of a fixed relational database schema.

Quick Facts
RoleSole developer
ContextAdilas customer e-commerce feature
TechAdilas application stack, SQL database
ComplexityMost challenging project at the time

The Problem

An Adilas e-commerce customer needed a way to attach flexible, customer-defined attributes - "parent attributes," presented to shoppers as tags - to products, so shoppers could filter and search inventory by attributes that didn't exist as fixed database columns and would vary customer to customer.

My Role

Sole developer for the feature, from data model design through the e-commerce-facing display and search integration.

What I Built

  • Five distinct tag types - text, text dropdown, number, toggle, and number dropdown - each presenting and validating information differently.
  • Per-tag configuration: sort order, which categories a tag can appear in, whether it's required, and whether it shows and/or is searchable on the public storefront.
  • An e-commerce-facing display and search layer so shoppers could filter inventory directly by these tags once configured and attached to items.

Technologies & Approach

Built on the Adilas application stack against a relational SQL database, where the data model itself had to stay flexible even though the underlying schema wasn't.

Relational Database Design Dynamic Schema Modeling E-commerce Search

Challenges

Unlike most features up to that point, this one worked against an unknown, variable number of possible database entries per item rather than a fixed set of fields - and displaying that variable data correctly and performantly inside an existing e-commerce UI added a second layer of difficulty. This was, at the time, the most complex project I'd taken on.

How They Were Solved

I modeled each tag type's configuration and values separately from the "core" item record, so an item could carry any number of tags without schema changes per customer, and built the storefront display/search logic to read that configuration at render time - the same general idea I later reused (in modern JavaScript) for this DevDocs platform's own automatic tag/search index.

Outcome & Value Created

A reusable, customer-facing product tagging feature that increased searchability on the storefront for the customer it was built for, and measurably leveled up my own comfort with complex, variable-shape data modeling.
